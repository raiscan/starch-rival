# pstack port maintenance

Keep this a small compatibility port of canonical poteto pstack. User and consuming repository instructions override workflow defaults. Do not introduce community-fork policies, global activation, extra approval ceremonies, or independent scheduling infrastructure.

- `upstream/` is a Git submodule of canonical `cursor/plugins`, with the source package at `upstream/pstack/`. Keep its files verbatim. Refresh the gitlink and `upstream.json` together through `scripts/pstack.py prepare-sync`; the manifest commit and subtree hash, checked-out submodule HEAD, and generated `port-manifest.json` must agree.
- Clone with `--recurse-submodules`, or run `git submodule update --init -- upstream` in an existing clone and each new task worktree before building. Repeat after integration changes the gitlink. Never force over dirty submodule work. Build/validation must fail clearly on an uninitialized or mismatched source rather than fetching implicitly.
- `port/` owns platform adaptation, setup, and model defaults. `scripts/` and `tests/` own deterministic packaging, installation, and sync checks. `dist/` is generated and ignored; never edit it.
- Preserve the complete upstream supporting tree and original invocation policy. Codex and Claude builds differ only where their metadata formats require it.
- Keep exact `claude-sonnet-5-5` as the required independent reviewer. Read `port/PORT.md` for delegation and unavailable-model handling. Obtain its read-only review before completing substantive code or workflow changes to this port. One review of unchanged final work is enough; new material risk is the reason to repeat it. This is an agent workflow requirement, not an attestation supplied by build/install tooling.
- Use isolated `.worktrees/` branches named `feature/ai-*` or `bugfix/ai-*`. Never switch the main workspace branch or overwrite unrelated work. Account for all changes before cleanup.
- Run `python3 -m unittest discover -s tests -v` and `python3 scripts/pstack.py build`. Validate the complete supporting-file inventory, bytes, and modes against the defined adaptations. Also inspect generated links, model routing, explicit invocation, install collisions, and changed sync behavior as appropriate. Do not claim a model review, install, scheduler activation, push, or PR that did not complete.
- Maintenance commands resolve the primary checkout through `git worktree list` and share its lock, cache, and candidate worktrees. Pin scheduled maintenance there. Preparation initializes and moves only the candidate's submodule; it must preserve the primary checkout's source and active skills. Compare the pstack subtree, not unrelated monorepo changes. `candidate_pending` means a changed tree already has a valid prepared candidate; it does not mean review succeeded. Do not repeat its agent/tests/reviewer on every tick or automatically recover a failed/lost agent. Explicit user resumption may reuse that candidate; newer upstream trees get separate candidates without deleting older work.
- Install only from the clean primary checkout on `main`. Installation snapshots the integrated source and rewrites concrete local Markdown references to absolute paths within that immutable release; builds and candidate work must not mutate active skills.
- Updating this repository does not itself authorize changing a user's model file, scheduler, credentials, trust, or installed skills. Follow the user's chosen delivery and installation scope. The public port is `https://github.com/raiscan/starch-rival`; its `origin` is separate from the canonical upstream submodule.
